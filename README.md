# Портфолио графического дизайнера

Статический сайт (без сборки) для GitHub Pages: русская и английская версии, страницы кейсов, админка `/admin/`.

- **Сайт**: `index.html` (главная) и `work.html?slug=…` (кейс). Всё содержимое берётся из `data/site.json` (тексты, цвета, разделы) и `data/works.json` (работы и категории).
- **Админка**: `admin/` — редактирование текстов, работ, изображений, категорий, цветов; предпросмотр; публикация коммитом в репозиторий.

## 1. Публикация на GitHub Pages

1. Создайте на GitHub **публичный** репозиторий (например, `portfolio`). Пустой, без README.
2. В папке проекта выполните (подставьте свой логин и имя репозитория):

   ```bash
   git remote add origin https://github.com/ВАШ-ЛОГИН/portfolio.git
   git push -u origin main
   ```
3. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main`, папка `/ (root)` → Save**.
4. Через минуту сайт появится по адресу `https://ВАШ-ЛОГИН.github.io/portfolio/`, админка — по адресу `https://ВАШ-ЛОГИН.github.io/portfolio/admin/`.
5. Чтобы ссылка красиво выглядела в мессенджерах и соцсетях, один раз пропишите адрес сайта и закоммитьте результат:

   ```bash
   node tools/set-url.mjs https://ВАШ-ЛОГИН.github.io/portfolio/
   git add -A && git commit -m "Адрес сайта" && git push
   ```

## 2. Первый вход в админку

Админка меняет файлы прямо в репозитории через GitHub API, поэтому ей нужен личный токен.

1. GitHub → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. **Repository access** → *Only select repositories* → выберите репозиторий сайта.
3. **Permissions → Repository permissions**: *Contents — Read and write*; *Pages — Read* (по желанию, для статуса публикации).
4. Нажмите *Generate token* и скопируйте токен (он показывается один раз).
5. Откройте `…/admin/`. Репозиторий определится сам. Вставьте токен, придумайте **логин и пароль** (от 10 символов). Дальше вход — по логину и паролю.

### Как устроена защита

GitHub Pages — статический хостинг: серверной части нет, поэтому логин и пароль нельзя проверить «на сервере». Вместо этого:

- токен хранится в браузере **только в зашифрованном виде** (PBKDF2 600 000 итераций → AES-GCM); логин и пароль — это ключ к нему;
- без вашего токена страница `/admin/` бесполезна: изменить файлы в репозитории может только владелец токена;
- после нескольких неверных попыток вход замедляется, а после часа бездействия админка блокируется;
- токен ограничен одним репозиторием и правом на файлы; его можно в любой момент отозвать на GitHub.

На каждом новом устройстве настройку проходят заново (токен вводится ещё раз). Не используйте админку на чужих компьютерах.

## 3. Как пользоваться админкой

| Раздел | Что можно делать |
|---|---|
| Работы | добавлять и удалять работы, менять порядок, скрывать, загружать изображения и видео (сжимаются в браузере в WebP), выбирать обложку и кадры для арки на главном экране |
| Категории | добавлять, переименовывать, менять порядок |
| Тексты | все тексты сайта на русском и английском, контакты, тезисы, список навыков, отзывы, подписи кнопок, название и описание для поиска |
| Оформление | цвета сайта, включение и отключение разделов |
| Публикация | список изменений и кнопка «Опубликовать». Все правки до этого лежат в браузере как черновик |
| Настройки | смена логина и пароля, замена токена, резервная копия текстов |

Правки попадают на сайт после **«Опубликовать»**; GitHub пересобирает страницу примерно за минуту. Кнопка **«Предпросмотр»** показывает сайт с вашими правками, на компьютере и в ширине телефона.

Совет: добавляйте только настоящие отзывы. Раздел «Отзывы» выключен и не показывается, пока в нём нет записей.

## 4. Структура

```
index.html, work.html      страницы сайта
css/, js/                  стили и скрипты сайта
data/site.json             тексты, тема, разделы
data/works.json            категории и работы
assets/works/<slug>/       изображения и видео работ
assets/fonts/              шрифты (Prata, Onest, Marck Script — свои копии)
admin/                     админка
tools/                     вспомогательные скрипты (на сайт не влияют)
```

## 5. Работа с кодом локально

Нужен Node.js 20+.

```bash
npm install
npm run serve        # сайт на http://localhost:4173
npm test             # проверка шифрования и публикации через API (на имитации GitHub)
npm run e2e          # сквозной тест админки в браузере Edge (имитация GitHub, ничего не трогает на настоящем GitHub)
```

`tools/seed.mjs` и `tools/manifest.mjs` — разовая подготовка начального набора работ из исходной папки; для повседневной работы не нужны (всё делает админка).

## 6. Права и конфиденциальность

В портфолио показаны корпоративные материалы, выполненные в штате. Убедитесь, что работодатель не против публичного показа, и скрывайте любую работу переключателем «Показывать на сайте». В работах нет контактов частных лиц; в визитках используются обезличенные данные.
